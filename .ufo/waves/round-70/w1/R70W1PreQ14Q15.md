## lint_entry.py judgment (what LINT_Q14=0 / LINT_Q15=0 do and do not prove)

`python3 -B corpus/lint_entry.py --entry <candidate bytes>` → `LINT_QMAP=0; LINT_Q14=0; LINT_Q15=0; LINT_HEADER=0`, exit 0. `--self-test` → `SELFTEST OK`, exit 0 (shown able to fail on all four classes). Planted-defect probes on synthetic entries in scratch:

Can see: a single backticked lowercase hex run with a mismatched count is flagged (probe `ascii-mismatch` → `LINT_Q14=1 [9]`); a fake id in the shape "at `deadbeef`" would be flagged as unresolvable.

Cannot see (each demonstrated with `LINT_Q14=0`/`LINT_Q15=0` on a defective fixture):
1. Multi-run clauses are skipped entirely (`two-runs-wrong-count` with three runs and a wrong count → `LINT_Q14=0`): any clause with ≠1 run and ≠1 count is silently passed. The entry's load-bearing sentence (entry.md:50) is itself in this blind class — its hex run is quoted outside backticks in a fence, so the lint cannot check the 16-byte/32-char claim at all; only my manual decode above covers it.
2. Uppercase/unbackticked hex is invisible (`uppercase-run-wrong-count`: `FFFFFFFF` (5 bytes) → `LINT_Q14=0`); the regex is lowercase-backticked only. Covers entry.md:86's `0xFFFFFFFF`.
3. Fence content (all tool JSON) is out of scope, so the `magic_ascii`/`magic_hex` pair at entry.md:105 is unchecked.
4. Q14's third clause — ASCII rendering decodes from the run — is not mechanized: the `ascii-mismatch` flag was for the length, while ASCII `Zzap` vs actual `main` passed silently.
5. Q15 only fires when `commit|base|tip|since|at` immediately precedes a backticked 7-40 hex token: `tree id `deadbeef`` and "See `deadbeef` at …" both → `LINT_Q15=0`. A fake id introduced any other way lands unseen.
6. Advisory (lint defect, not entry defect): the `\bat\s+` prefix false-positives on ordinary English — my probe sentence "… end at `504b0506` (9 bytes)" produced `LINT_Q15=1 [(9, '504b0506')]` for a CRC that is no git id at all. A future entry quoting any lowercase-hex token after "at" would draw a bogus Q15 finding.
