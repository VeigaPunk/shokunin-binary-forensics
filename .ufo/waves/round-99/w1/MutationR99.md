## 1. Baseline exit 3 (routed defect 5): cause and fix

**Observed on frozen v7** (`reports/round-98/c1_k_admit_counter7.py`, sha `59c9930a…`, the pinned unmutated copy generated by the harness):

- `mutate7.py --counter reports/round-98/c1_k_admit_counter7.py --out <S>/repro7 --selftest --jobs 4` → **harness rc=3**, with a
  full 249-mutant site table written and no detector output.
- The harness's own unmutated copy, run directly in the same scratch with the same env
  (`TMPDIR`, `HYAKU_SCRATCH`, `PYTHONUTF8=1`, `cd <lane>`): `python3 -B <S>/repro7/mutants/unmutated.py --self-test` → **rc 0**,
  stdout `SELFTEST_C1V7=OK legs=55`. (`repro/unmutated-selftest.out`, `.err` empty.)
- The recorded control `reports/round-98/controls/selftest-v7-frozen.log` reads `SELFTEST_C1V7=OK legs=55`, `# rc=0`.

**Cause (not environment, not path, not scratch, not profile):** mutate7's baseline check used
`SELFTEST_PASS = re.compile(r"SELFTEST_C1V\d+=pass\b")`. The counter has never printed `=pass`; it prints
`=OK` or `=FAIL` (`print(f"SELFTEST_C1V7={'OK' if not fails else 'FAIL'} legs={total}")`, v7 L1422).
So a genuinely passing counter was classified as a baseline failure and the harness exited 3 before any
mutant ran. The same regex would also have marked every healthy mutant as "killed" had the baseline check
been bypassed, so the defect was a false verdict in both directions.

**Fix in mutate8:** `SELFTEST_PASS` accepts `=OK` or `=pass`; `SELFTEST_FAIL` matches `=FAIL`. The baseline
exits 3 only when rc≠0, no pass label, or a FAIL label is present. Mutants are judged by the same
predicate. When the counter source supports `--work`, baseline and mutants are both invoked with
`--work <out>/st` (identical on both sides).

**Evidence of the fix (fail-closed both ways):**

| run | command (abbrev.) | rc | output |
|---|---|---|---|
| fixed baseline, real v7 | `mutate8.py --counter reports/round-98/c1_k_admit_counter7.py --out <S>/fix7 --selftest --profile c02 --label V7` | **0** | `BASE_SELFTEST rc=0 label=SELFTEST_C1V7=OK legs=55`; `MUTANT_SELFTEST_V7=215/233`; `SURVIVORS_SELFTEST=…` (`validate/baseline-fixed-v7.out`) |
| broken counter (v7 copy whose print is forced to `SELFTEST_C1V7=FAIL legs=…`) | `mutate8.py --counter <S>/broken/counter7x.py --selftest …` | **3** | exits before detectors (`validate/baseline-broken.*`) |

Note on this validation run: `--base-counter` was defaulted to v7 and the counter was v7, so the new-leg
operator classes were empty (`NEW_LEGS_DERIVED=none`, 233 mutants). It validates the baseline logic only.

## 4. d-host (carried survivor)

- **Why it survives in v7:** the host check (v7 `check_receipts`, `if host not in HOST_ALLOWLIST: fails.append(...:host...)`) is
  the only check that fails for a foreign host. The only foreign-host vector, V27 (`fabricated-body-foreign-host`), also fabricates
  its body and has no fetch-log line and a `quote-irrelevant` quote, so other sub-checks fail. Removing the host sub-check leaves
  V27 failing `C1_RECEIPTS`. The tree detector cannot see a host-only change either, since every archive tree uses github hosts.
- **Whether a v8 leg kills it:** the tree detector does not (`d-host=0/1`, unchanged). The self-test does, through the new
  vector **V27b `host-only-foreign`** (`_host_only_delta` in v8): only the first receipt's `fetch_url` changes host; the body,
  hash, quote and fetch-log line are untouched. v8's exercise asserts `check_receipts` returns False with WHY exactly
  `S502:host:'dlang.org'`. With the sub-check removed the mutant gives ok, so the self-test fails
  (`SELFTEST FAIL: c02:V27b-host-only-foreign: WHY is not the host alone: ok`) and the mutant is killed. The proposal was sent to
  ExecCounterV8 (`agent://ExecCounterV8`); the counter now carries it in the final bytes.
- **Observed caveat:** the same V27b exercise reports `failing=C1_SOURCES` on the mutant, i.e. the host-only change also trips
  the source-registry cross-check (the URL no longer matches the SOURCES row). `[INFERENCE: the source-row check compares the receipt's URL]`.
  So V27b is not a single-leg isolate; the kill comes from the direct `check_receipts` assertion, not from `C1_RECEIPTS` alone.
  The L1 should know that V27b's leg isolation is not clean.
