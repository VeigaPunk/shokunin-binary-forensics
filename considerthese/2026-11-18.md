## Self-improvement proposals (propose only, not acted on)

1. **Out-of-scope register per capability.** Each capability should list the format variants it does *not* handle (for example, encrypted ZIP entries, fragmented carving, big-endian TIFF edge cases), so a "no finding" can be told apart from "not covered". Today the corpus says what it can do but not where it stops.
2. **Retrospective calibration scoring.** When a later case or source confirms or refutes an earlier claim, record the stated confidence next to the outcome and keep a running Brier-style score per confidence tier. This turns the confidence tiers proposed on 11-16 into something measurable instead of self-declared.
3. **Embedded-timestamp consistency check.** Many formats carry their own clocks (PE `TimeDateStamp`, ZIP DOS date/time, PNG `tIME`, PDF `/CreationDate`, OOXML `docProps/core.xml`). A small cross-check noting when these disagree with each other or with the container's metadata adds a forensic signal the lane does not cover yet. It should be labeled as a sanity check, never as proof of when a file was made.
4. **Carving case against a public ground-truth image.** A file-carving case on a public, documented test image (NIST CFReDS or Digital Corpora sets ship with ground truth) would cover recovery from unallocated or fragmented space. That is a depth gap next to the current whole-file identification work, and the scoring against ground truth comes built in.
