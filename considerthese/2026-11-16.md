## Self-improvement proposals (propose only; not acted on)

New relative to the Oct 20 to Nov 15 sets.

1. **Truncation-offset negative controls.** For each of the five capabilities, run the same valid input truncated at a few structural boundaries (mid-header, mid-index, just before a trailer). This tests whether a capability says "partial parse, stopped at offset N" or quietly reports a clean result. The polyglot control from 11-15 tests a second valid reading; this one tests a missing ending.
2. **Confidence tiers on every finding.** Label each identification as signature-only (magic bytes), structurally parsed (headers and offsets check out), or semantically validated (decoded content is consistent end to end). Today these three levels read the same in a case write-up, and that hides how much was really checked.
3. **Pin tool versions in receipts.** Record the exact version of every external tool a case used (for example libmagic/`file`, binwalk, a format's reference parser) next to its result. A later disagreement can then be traced to a tool change rather than re-argued. This is narrower than the C15 release watch from 11-11: it is about reproducing past results, not tracking new releases.
