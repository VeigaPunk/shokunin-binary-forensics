## New proposals (propose only, not acted on)

1. **Look at PE delay-load and ordinal-only imports, not just the main import table.** Many import-table views, and the imphash proposed on 2026-11-25, read only IMAGE_DIRECTORY_ENTRY_IMPORT. APIs pulled in through the delay-load directory (IMAGE_DIRECTORY_ENTRY_DELAY_IMPORT) or imported by ordinal only stay invisible there, and malware uses both to hide capability. Record all three sources per binary, resolve ordinals against known DLL export tables where possible, and mark any capability claim that rests on the main import table alone as incomplete.
2. **Use ELF symbol versioning to bound when and where a binary was built.** The .gnu.version_r (DT_VERNEED) section lists the highest symbol versions the binary needs (for example GLIBC_2.34). That sets the oldest glibc, and so the oldest distro release, that can run it, and gives an "earliest possible build" bound that is hard to fake without breaking the binary. Compare it with embedded timestamps and compiler notes, and record it as a lower bound only: a binary built on a new system against an old sysroot will look older than it is.
