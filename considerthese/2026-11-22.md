## New proposals (propose only, not acted on)

1. **Code-signature coverage check for signed executables.** For PE inputs, parse the Authenticode certificate table and record which byte ranges the signed digest actually covers, flagging any data appended after the signature blob or hidden in excluded regions (a known technique for smuggling payloads into validly signed files). Report "signature valid" and "all bytes covered" as separate claims, since the first does not imply the second.
2. **Debug-symbol linkage records.** Extract the PE CodeView RSDS record (PDB GUID + age + path) and the ELF `.gnu_debuglink` name + CRC32, and record them in the receipt so a binary can be paired with its exact symbol file (or shown to be mismatched). This is distinct from toolchain attribution: it identifies a specific build, not a compiler family, and the embedded PDB path often leaks build-host details worth noting as evidence.
