## New proposals (propose only, not acted on)

1. **Import-table hashing (imphash for PE, telfhash for ELF).** Record the import hash next to the file hash for every binary a case touches. Two samples with different SHA-256 but the same imphash/telfhash usually share a build lineage, which complements fuzzy hashing of bytes. Calibrate it: note the import count with each hash, and treat a match on fewer than about 10 imports, or on a packer stub's tiny import table, as weak evidence only.
2. **.NET (CLR) metadata as its own layer.** For managed PE files, read the CLI header and metadata streams: module version ID (MVID, a GUID regenerated on each build), assembly name/version, referenced assemblies, and the TypeRef/MemberRef tables. Native PE checks see a .NET binary as a stub that imports only `mscoree.dll`, so claims about its behavior or provenance need this layer, and the MVID gives an exact build identity that survives renaming.
