# Reverse-engineering resource atlas: where each kind of claim gets its outside oracle

## Scope

This entry organizes 305 registry rows (S110–S414) by the work an RE evidence-ledger practitioner has to do: judge a disassembly or decompiler listing, derive an expected value from a specification, decide what a parser really accepts, label a capability or diff claim, pick an extractor for a packaging format, carve firmware, bound what a hash or signature proves, recognise obfuscation vocabulary, and train judgment on checkable material. It is a reading map. Every sentence about a source says only what that row's quote and scope say, at the pinned revision; it is not a claim that a tool works, was run, or is accurate on any target.

What it is not: not a market census, not an installation or readiness claim, not authorization for any live-target, exploitation, DRM or protection-defeat activity (PROVINCE.md refusals stand), and not a replacement for the lane's byte-oracle discipline: a row supplies a place to derive an expected value; the derivation still has to be run and recorded (Q03, Q11).

## Observation / inference / unknown

- **Observation.** Each row's located quote exists at the cited URL as of its `opened` date (re-matched by script or by hand, see `verified-at`). The host has the tools listed in `reports/round-73/tool-probes.md`, each with a version command and one probe against a system binary.
- **Inference.** The `teaches` sentence of each row (what the quote means for a ledger) and the routing below are the integrator's reading of those quotes. A paper abstract supports only what the abstract says; a README supports only the project's own statement of scope.
- **Unknown.** Whether any listed tool is accurate on a given artifact; whether pages changed after `opened`; whether single-opener rows' quotes are still present; whether obscure community material (tier C rows) remains maintained.
